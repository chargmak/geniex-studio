# Local GenAI beyond LLM/VLM on Snapdragon X Elite (Windows 11 arm64) — research results, Aug 2026

Context confirmed locally: `geniex --help` (v0.4.0) exposes only `pull/remove/clean/list/model(set-type llm|vlm, list)/infer/serve/run/config/version/update`; `geniex serve` = `/v1/chat/completions`, `/v1/completions`, `/v1/models` only (no `/v1/embeddings`, no `/v1/audio/*`, no images). GenieX is Qualcomm's successor to Nexa SDK (Qualcomm acquired Nexa AI, July 2026; "developer preview", roadmap only says "expanded model coverage") — https://www.qualcomm.com/developer/blog/2026/06/geniex-developer-preview , https://geniex.aihub.qualcomm.com/llms.txt

## The four "engines" that actually reach the Hexagon NPU today (besides GenieX)

1. **ONNX Runtime + QNN EP (`onnxruntime-qnn`, plugin EP 2.x, native ARM64 only)** — the mechanism behind Qualcomm AI Hub Windows apps. Python (3.11–3.14) / C++ / C#. **Not in `onnxruntime-node` prebuilt binaries** (win-arm64 node ships CPU, DirectML, WebGPU-experimental only; plugin-EP registration documented for C++/Python/C#, no Node API). https://github.com/onnxruntime/onnxruntime-qnn , https://onnxruntime.ai/docs/execution-providers/QNN-ExecutionProvider.html , https://onnxruntime.ai/docs/execution-providers/plugin-ep-libraries/usage.html , https://github.com/microsoft/onnxruntime/blob/main/js/node/README.md
2. **QAI AppBuilder (`pip install qai-appbuilder`, v2.49.0, 2026-08-11)** — Qualcomm's Python/C++ wrapper over QAIRT that runs QNN context binaries on the NPU; ships ready samples: **Stable Diffusion v1.5 / v2.1 / v3.5-Medium (1024², 8 steps)**, **PiperTTS-EN (RTF<1, ~0.5–2 s/sentence)**, Whisper tiny/base, **nomic_embed_text**, EasyOCR, CLIP, Qwen-VL, OpusMT, super-res/inpainting, plus Gradio WebUIs (StableDiffusionApp, ImageRepairApp, GenieWebUI) and an OpenAI-compatible "GenieAPIService" (LLM only). Wheels are cp312 → you would need a Python 3.12 arm64 venv (you have 3.14). No Node bindings. https://github.com/qualcomm/qai-appbuilder , https://github.com/qualcomm/qai-appbuilder/tree/main/samples
3. **Windows AI Foundry / Windows AI APIs (Windows App SDK, WinRT, MSIX identity + `systemAIModels` capability)** — on Copilot+ PCs these run on the NPU: Phi Silica (being replaced by "Aion Instruct" Oct–Nov 2026), **Image Generation (SD-based: text-to-image, img2img, Magic Fill/inpaint, Restyle, Coloring-book; NPU-only; WinAppSDK 2.0-Experimental3; several-GB optional model via `EnsureReadyAsync`)**, **Speech Recognition (batch + streaming, preinstalled NPU model, WinAppSDK 1.7.1+)**, OCR, Image Super Resolution, Image Description, Segmentation, Object Erase, Video Super Resolution. **New (2026-07-27, public preview): `@microsoft/winappcli` + `@microsoft/dynwinrt` dynamic WinRT projections let Electron/Node call these APIs directly from JS (x64 + arm64), with debug package identity via `npx winapp node add-electron-debug-identity`.** https://learn.microsoft.com/en-us/windows/ai/apis/ , https://learn.microsoft.com/en-us/windows/ai/apis/image-generation , https://learn.microsoft.com/en-us/windows/ai/apis/speech-recognition , https://devblogs.microsoft.com/ifdef-windows/a-new-way-to-bring-native-windows-apis-to-javascript-introducing-dynamic-api-projections-for-node-js/ , https://learn.microsoft.com/en-us/windows/apps/dev-tools/winapp-cli/guides/electron-js-phi-silica , https://github.com/microsoft/windows-ai-electron
4. **Foundry Local (GA Apr 2026, v1.1 May 2026)** — OpenAI-compatible local REST (`foundry service start`) + JS/Python/C#/Rust SDKs (JS SDK is a Node-API addon, no koffi). Chat, **embeddings (`qwen3-embedding-0.6b` etc.)**, **Whisper transcription + live transcription (Nemotron streaming)**, Responses API/tools, Qwen3.5 VLM. Auto-picks QNN EP on Snapdragon, **but the QNN-NPU catalog is a handful of older LLMs (phi-3.5-mini, phi-3-mini, deepseek-r1-7b/14b, qwen2.5-1.5b/7b); Whisper and embeddings run CPU only on Snapdragon; users report NPU models not listed / crashes.** https://learn.microsoft.com/en-us/azure/foundry-local/what-is-foundry-local , https://devblogs.microsoft.com/foundry/foundry-local-v1-1/ , https://learn.microsoft.com/en-us/azure/foundry-local/how-to/how-to-generate-embeddings , https://github.com/microsoft/foundry-local/issues/783 , https://github.com/microsoft/Foundry-Local/issues/738 , https://github.com/microsoft/foundry-local/issues/719

Also relevant: Windows ML 2.x ships the QNN EP as an OS component (current QAIRT 2.45.41, KB5096135 May 2026) usable from WinRT/C# apps via `ExecutionProviderCatalog` — https://learn.microsoft.com/en-us/windows/ai/new-windows-ml/supported-execution-providers

## Per-modality findings

**(a) Image generation — YES on the NPU, SD-class only.**
- Qualcomm AI Hub ships SD 1.5 / SD 2.1 / ControlNet-Canny compiled for X Elite (w8a16). Measured on X Elite NPU: UNet 157 ms/step, VAE 258 ms, text enc 8 ms → 512² image in ~3.5–4 s at 20 steps (X2 Elite ~2×). https://huggingface.co/qualcomm/Stable-Diffusion-v2.1 , https://aihub.qualcomm.com/models/stable_diffusion_v2_1
- Reference Windows app: `pip install qai-hub-apps; qai-hub-apps fetch stable_diffusion_windows_py --model stable_diffusion_v2_1 --chipset qualcomm-snapdragon-x-elite` (Python arm64 native, `onnxruntime==1.24.4 onnxruntime-qnn==2.3.0`, `python demo.py --prompt ... --num-steps 20`). https://github.com/qualcomm/ai-hub-apps (dirs `stable_diffusion_windows_py`, `whisper_windows_py`, `sam3_segmentation_windows_py`)
- SD 3.5 Medium 1024² on NPU via QAI AppBuilder sample (models auto-downloaded per X Elite/X2 Elite; no published latency; expect tens of seconds). https://github.com/qualcomm/qai-appbuilder/tree/main/samples/GenerativeAI/Image_Generation
- Windows AI Foundry ImageGenerator (SD/SDXL-based, 6-step default, content filters) callable from Electron via winappcli — cleanest "no Python" path, but WinAppSDK 2.0-Experimental + Windows Update model download.
- SDXL / FLUX / video-grade models: no NPU port; FLUX/SDXL on Adreno X1 (4.6 TFLOPS) via DirectML EP (which onnxruntime-node does have on win-arm64) is technically possible but no published X Elite numbers and expect minutes per image; Amuse is AMD-focused with no Snapdragon support; A1111/ComfyUI have no Snapdragon builds. https://github.com/AUTOMATIC1111/stable-diffusion-webui/discussions/16344 , https://amd.com/en/blogs/2025/worlds-first-bf16-sd3-medium-npu-model.html
- Riffusion: not in the current AI Hub catalog.

**(b) Video generation — NOT practically available.** Qualcomm AI Research "Neodragon" (ICLR 2026) generates 2 s 640×1024 video in ~6.7 s on Snapdragon 8 Elite-class NPU; the paper's X Elite path was 184 s before distillation, code/weights released as PyTorch (no Windows QNN app). Wan/LTX/SVD/AnimateDiff have no NPU ports; on Adreno via DirectML they would take many minutes per clip. Only "video super resolution" is productized (Windows AI API). https://arxiv.org/abs/2511.06055 , https://qualcomm-ai-research.github.io/neodragon/ , https://github.com/Qualcomm-AI-research/neodragon , https://learn.microsoft.com/en-us/windows/ai/apis/video-super-resolution

**(c) Speech-to-text — YES on the NPU, several routes.**
- AI Hub Whisper tiny/base/small/medium/large-v3-turbo(+quantized), Distil-Whisper, Zipformer for X Elite; whisper-large-v3-turbo on X Elite NPU: encoder 627 ms per 30 s window, decoder ~8 ms/token (≈RTF 0.1). Windows app supports mic streaming (`python demo.py --stream-audio-device N`). https://huggingface.co/qualcomm/Whisper-Large-V3-Turbo , https://github.com/qualcomm/ai-hub-models
- Windows AI Speech Recognition API (NPU, streaming, from Electron via winappcli).
- GenieX itself: audio input via `gemma-4-E2B-it-qat-q4_0-gguf` mmproj on NPU (`input_audio` content part in `/v1/chat/completions`) — a workable "transcribe" fallback with zero new runtimes. https://geniex.aihub.qualcomm.com/en/tutorials/audio-input.md
- Foundry Local Whisper/live transcription: CPU on Snapdragon. Third-party FP16 whisper-large-v3-turbo QNN packs exist (FluidInference). https://huggingface.co/FluidInference/whisper-large-v3-turbo-qnn

**(d) Text-to-speech — YES.** NPU: AI Hub PiperTTS-EN/DE/IT and MeloTTS-EN/ES/ZH; QAI AppBuilder pipertts sample (4 QNN context binaries, ~0.46 s per phrase). CPU (Node-native): sherpa-onnx (Kokoro-82M, Piper, VITS) has Node bindings and Windows arm64 builds; Windows built-in natural voices via WinRT SpeechSynthesizer / browser `speechSynthesis`. https://github.com/k2-fsa/sherpa-onnx , https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/index.html

**(e) Embeddings for RAG — YES.** NPU: AI Hub Nomic-Embed-Text, MiniLM-v2, OpenAI-CLIP; QAI AppBuilder `nomic_embed_text` sample; academic X Elite result: EmbeddingGemma-300M on NPU 3,325 tok/s vs 367 CPU (9×), 12× less energy (arXiv 2606.11257). CPU: Foundry Local `/v1/embeddings` (qwen3-embedding-0.6b), transformers.js/onnxruntime-node (arm64 CPU/WebGPU). GenieX has no embeddings endpoint. https://arxiv.org/html/2606.11257v1

**(f) Windows AI Foundry / Foundry Local** — see engines 3 & 4 above. Note Phi Silica → Aion Instruct transition (Oct/Nov 2026) and that Windows AI APIs need MSIX/package identity.

**(g) llama.cpp ggml-hexagon** — LLM matmul offload only (Q4_0 best; MXFP4/Q8 partial), no whisper.cpp/embedding-specific NPU path; on Windows the HTP op libraries need test-signing (`bcdedit /set TESTSIGNING ON` + self-signed cat) unless you use a vendor build like GenieX; ~50 tok/s on 1B, ~10–16 tok/s on 7–8B; FastRPC dispatch overhead is the bottleneck. llama.cpp OpenCL backend covers Adreno GPU (GenieX `--compute gpu`). https://github.com/ggml-org/llama.cpp/blob/master/docs/backend/snapdragon/README.md , https://github.com/ggml-org/llama.cpp/blob/master/docs/backend/snapdragon/windows.md , https://github.com/ara142/llama-cpp-hexagon-npu

## Feasibility matrix (X Elite, 45 TOPS Hexagon + Adreno X1 + 12-core Oryon)

| Capability | Available today? | Runs on | Tool / SDK | Rough X Elite perf | How a Node/web UI invokes it |
|---|---|---|---|---|---|
| Chat / VLM | Yes | NPU/GPU/CPU | GenieX serve | model-dependent | HTTP `127.0.0.1:18181/v1` (already) |
| Text-to-image SD1.5/2.1 512² | Yes | NPU | AI Hub `qai-hub-apps` (ORT-QNN, Py3.11+ arm64) or QAI AppBuilder | ~3.5–4 s/img @20 steps | Spawn Python sidecar / tiny FastAPI wrapper |
| Text-to-image SD3.5-Medium 1024² | Yes (sample) | NPU | QAI AppBuilder (Py3.12 wheel) | unpublished, likely 20–60 s | Python sidecar |
| Text-to-image + inpaint/restyle (OS model) | Yes (experimental SDK) | NPU only | Windows AI ImageGenerator | ~seconds (6 steps) | Electron + `@microsoft/winappcli` bindings, MSIX identity |
| SDXL / FLUX | Not on NPU | Adreno via DirectML EP (onnxruntime-node) | DIY | minutes/img, untested | onnxruntime-node DML — experimental |
| Video generation | No (research only) | — | Neodragon weights (PyTorch) | 184 s→? for 2 s clip | Not viable in-app; offer cloud or "coming later" |
| Video super-res | Yes | NPU/CPU | Windows AI VSR API | realtime-ish | winappcli |
| Speech-to-text | Yes | NPU | AI Hub Whisper (ORT-QNN, mic streaming) / Windows AI SpeechRecognition / GenieX gemma-4 audio | Whisper-L-v3-turbo ≈0.1 RTF | Python sidecar; winappcli; or GenieX `input_audio` |
| Text-to-speech | Yes | NPU (Piper/Melo via AppBuilder) or CPU (sherpa-onnx Kokoro, WinRT voices) | see left | Piper ~0.5 s/sentence | Python sidecar or sherpa-onnx-node / browser speechSynthesis |
| Embeddings / rerank | Yes | NPU (Nomic/MiniLM/CLIP via AppBuilder or ORT-QNN) or CPU (Foundry Local, transformers.js) | see left | NPU ~3.3k tok/s (EmbeddingGemma) | Foundry Local `/v1/embeddings` (CPU) or Python sidecar (NPU) |
| OCR / image describe / segment / erase / super-res | Yes | NPU | Windows AI APIs; AI Hub SAM3/EasyOCR | fast | winappcli or Python sidecar |
| Foundry Local NPU LLMs | Partial (old catalog) | NPU (QNN) | Foundry Local | ~ | OpenAI REST |

Practical implication for the app: keep GenieX as the LLM/VLM core; add an optional **Python-arm64 "NPU sidecar"** (qai-hub-apps / qai-appbuilder wrapped in a small local HTTP server) for SD, Whisper, Piper, embeddings on the NPU; and/or use **Electron + winappcli** to hit Windows AI Foundry image-gen/speech/OCR without Python. Be explicit with the user that image gen is SD1.5/2.1/3.5-class (not FLUX/SDXL quality) and that local video generation is not realistic on this hardware.
