## 3. What GenieX is (docs "What is GenieX", README)
- "On-device Gen AI inference runtime built for Qualcomm platforms… community version of Qualcomm GENIE." **Developer preview.** BSD-3-Clause (LICENSE: Copyright 2024-2026 Qualcomm Technologies), NOTICE file, plus Qualcomm Terms of Use.
- Repo lineage: GitHub releases before `v0.3.0-alpha.1` (2026-06-11) are **NexaAI/nexa-sdk** releases (`nexa-cli_*` assets, v0.2.57–v0.2.73). GenieX is the Qualcomm-owned rewrite/rebrand of Nexa SDK ("the server has been rewritten since (`geniex serve`)"). Old nexa features (Stable Diffusion/Flux, TTS, ASR, embeddings, rerank, macOS/x86/CUDA) are **not** in GenieX.
- Repo stats (gh api): 8,306 stars, 1,043 forks, primary language Rust (model manager), plus Go (CLI + server, gin), C/C++ (SDK + plugins), Python, Kotlin. Topics: llm, on-device-ai, sdk, vlm, go, gpt-oss, llama3, qwen3, granite4, qwen3vl, gemma4, hexagon, local-ai, qualcomm, snapdragon. Default branch `main`, pushed 2026-08-14.
- Five entry points over one C SDK (`sdk/include/geniex.h`): CLI, Python SDK (`pip install geniex`, PyPI), Android SDK (`com.qualcomm.qti:geniex-android:0.3.1` on Maven Central per README; AAR v0.4.0 in releases), Docker (`docker.io/qualcomm/geniex:latest`, Linux ARM64 only), OpenAI-compatible server (`geniex serve`). Also a C/C++ SDK zip per release and a Go binding (`bindings/go`, used by the CLI).
- Two runtimes ("plugins"): `llama_cpp` (any GGUF; NPU via Qualcomm GGML Hexagon backend, Adreno GPU via OpenCL, CPU) and `qairt` (Qualcomm AI Engine Direct / QNN; pre-compiled per-chipset AI Hub bundles; **NPU only**).

- Snapdragon only — "no x86 or non-Snapdragon ARM build". ## 5. Compute units (semantics from docs + `notes/run.md` + source)
`--compute` / request `compute` / Python `device_map` / Android `compute_unit` aliases resolved by `geniex_resolve_device` in `sdk/src/device.cpp`:
| alias | device_id to SDK | n_gpu_layers | meaning |
|---|---|---|---|
| `npu` (default for both runtimes) | `HTP0` | `--ngl` (default -1 = all) | pinned single-session Hexagon HTP; deterministic; also flips KV cache to Q8_0 + flash-attn (llama.cpp) |
| `gpu` | `GPUOpenCL` | -1 | Adreno via OpenCL (llama_cpp only) |
| `cpu` | empty | forced `0` | pure CPU |
| `hybrid` | empty | -1 | llama.cpp per-tensor HTP+CPU scheduler — "**The fast path on Snapdragon**" per docs |
- QAIRT: NPU only; `cpu`/`gpu`/`hybrid` coerced to NPU **with a warning, never an error** in the SDK/serve/Android (docs' CLI reference contradicts itself, saying `--compute cpu` "returns an error" for AI Hub models; the SDK/notes say coercion+warning). Concrete ids `HTP0..HTP3`, `GPUOpenCL` pass through as `<plugin>:<device>` in Python `device_map`.
- Host-aware default (`cli/internal/config/compute.go`): chipset `qualcomm-qcs6490` / "dragonwing rb3 gen 2 vision kit" → default `cpu`.
- `notes/run.md` perf (X1E80100, Qwen3-1.7B Q8_0): hybrid ≈ 90 tok/s prefill, 27 tok/s decode, ~200 ms TTFT (Task Manager NPU pegged); pinned `npu` ≈ 60 tok/s prefill, 22 tok/s decode, ~350 ms TTFT (CPU pegged by host busy-wait). Note: this notes file still says "hybrid (default)" and uses `--device`; the current CLI flag is `--compute` and docs say default is `npu`.
- Verify NPU engagement: `GGML_HEX_VERBOSE=1` (look for `Hexagon Arch version vNN` / `libggml-htp-vNN.so`), Python `GENIEX_LOG=INFO` (`Found device: HTP0` = pinned path), Windows Task Manager NPU graph. `--compute hybrid` silently falls back to CPU if Hexagon driver can't load.
- Threadpool: offloaded paths log `threadpool tuned for offload: 6 threads pinned to cores [2, 8), strict, poll=1000` (override `n_threads` in `geniex_ModelConfig`).
- Q4_K_M suboptimal for HTP (some tensors fall to CPU); Q4_0 for a clean NPU run.
- HTP memory limits: issue #1244 (IQ-9075, gemma-4-26B-A4B): `--ngl` > 7 fails with `fastrpc_mmap failed`; workaround `--compute npu --ngl 7`; CLI shows generic "Model failed to load".

## 6. Models, naming, precision, hubs
- Model types: `llm` | `vlm` only (`geniex pull --model-type`, `geniex model set-type <model> [llm|vlm]`). Modalities: text (all), image (any VLM: QAIRT bundle or GGUF with image mmproj), audio (**llama_cpp only**, GGUF VLM whose mmproj carries a conformer encoder, e.g. `google/gemma-4-E2B-it-qat-q4_0-gguf`; QAIRT reports `audio: false` and fails with `GenieXError(-201201): Multimodal generation failed`).
- Name grammar: `org/repo[:precision]`. Canonicalization (`sdk/model-manager/crates/core/src/mapping.rs`): `ai-hub-models/<X>` (case-insensitive) → `qualcomm/<X>` (same cache entry); bare name without `/` → `qualcomm/<name>` (bare AI Hub id like `llama_v3_2_3b_instruct`); `https://huggingface.co/org/repo` prefix stripped; Docker Hub only via explicit prefixes `docker.io/`, `index.docker.io/`, `registry-1.docker.io/`, `hub.docker.com/r/` (or `--model-hub docker` with bare `ai/gemma3`); alias `qwen3` → `ggml-org/Qwen3-1.7B-GGUF:Q4_K_M`. Docker Hub models use `:<tag>` instead of a precision (default `latest`).
- Hubs (`--model-hub aihub|hf|docker|localfs`, auto-detected when omitted; Python `hub="auto"|"hf"|"localfs"`; Android `HubSource` AUTO(0)/HUGGINGFACE(1)/MODELSCOPE(2)/AIHUB(3)/VOLCES(4)/LOCALFS(127) — ModelScope re-introduction is open issue #1085).
  - **aihub**: pre-compiled QAIRT bundles (`metadata.json` + `.bin` shards, or AI Hub `.zip`), pulled via S3 protojson chain + remote ZIP64 parse; needs a chipset (auto-detected on Windows/Linux; Android must pass `chipset`); `geniex config get/set chipset` (interactive picker); DEFAULT_AI_HUB_VERSION pinned (v0.60.0 in v0.4.0). QAIRT models "need a `geniex.json`" (generated on import); adding a new QAIRT model requires registering it in `third-party/geniex-qairt/models/{llm,vlm}_model_registry.h` ("unknown model name" error otherwise). QAIRT VLM registry names e.g. `qwen3_4b_instruct_2507`, `qwen2_5_vl_7b_instruct`.
  - **hf**: any GGUF repo; interactive precision picker unless `:precision` given (`Q4_0 [1.2 GiB] (default)`, `Q8_0`, `F16`…); resumable, chunked parallel downloads; token priority `GENIEX_HFTOKEN` > `HF_TOKEN` > `~/.cache/huggingface/token`; `HF_ENDPOINT` honored (mirror). Gated models need license acceptance + token.
  - **docker**: `hub.docker.com/u/ai` GGUF images (Docker Registry V2 API), e.g. `geniex infer docker.io/ai/gemma3`.
  - **localfs**: `geniex pull local/<name> --local-path <dir|aihub.zip>` (implies `--model-hub localfs`); copies into cache (source can be deleted). GGUF dir may include `mmproj-*.gguf` for VLM; QAIRT dir must contain `metadata.json` + `.bin` shards (loose `.bin` without metadata not detected).
- Precision (llama_cpp): `Q4_0` (default, "Best NPU support in llama.cpp"), `Q8_0`/`F16`/`Q4_K_M`/`Q5_K_M` → "GPU / CPU", "Not optimized for Hexagon NPU"; MXFP4 recognised; quant tags case-insensitive. QAIRT: baked in — `w4a16` (most common), `w4`; also `W4A16` shown in issue as `qualcomm/Qwen3-1.7B:W4A16`.
- QAIRT runtime constraints: precision, context length and KV cache **baked into the bundle**; `--nctx` has no effect; Android rejects `nGpuLayers != 0`/`nCtx != 0` with `PARAM_NOT_SUPPORTED`; only `max_tokens`/`enable_thinking` tunable. `--sliding-window` (qairt only, CLI) evicts oldest context above an anchored prefix (`SlidingWindowNKeep` default 4) instead of erroring; llama_cpp "always context-shifts". QAIRT plugin rejects `stop` sequences (`--stop / --stop-file (stop sequences) is not supported by the qairt plugin`, error `-100016`) — see issue #1341.
- Verified/tested model lists: docs quickstart: `ai-hub-models/Qwen3-4B`, `ai-hub-models/Qwen2.5-VL-7B-Instruct`, `unsloth/Qwen3.5-0.8B-GGUF`, `Qwen/Qwen3-VL-2B-Instruct-GGUF`, `unsloth/Phi-4-mini-instruct-GGUF`, `google/gemma-4-E2B-it-qat-q4_0-gguf` (audio+vision, ~4.0 GiB), `google/gemma-4-E4B-it-qat-q4_0-gguf` (README), `unsloth/Qwen3-4B-GGUF:Q4_0`, `unsloth/Qwen2.5-Coder-3B-GGUF:Q4_0` (FIM), `qualcomm/Qwen3-VL-4B-Instruct` (tool-calling VLM). "For `Qwen3.5` and `Gemma4`, pick `llm` for now (multimodal support coming soon)" (CLI quickstart). `tests/models.json`: `unsloth/Qwen3-4B-GGUF:Q4_0`, `unsloth/gemma-4-E2B-it-GGUF:Q4_0` (vlm), MTP pair `google/gemma-4-26B-A4B-it-qat-q4_0-gguf:Q4_0` + `RachidAR/gemma-4-26B-A4B-it-qat-assistant-q4_0-gguf:Q4_0`, `qualcomm/Qwen3-4B`, `qualcomm/Qwen2.5-VL-7B-Instruct`. `bench-models.json` (llama_cpp Q4_0, devices cpu/npu/gpu/hybrid): `ggml-org/Qwen3-0.6B-GGUF`, `unsloth/Qwen3-1.7B-GGUF`, `unsloth/Qwen3-4B-GGUF`, `unsloth/Qwen3-4B-Instruct-2507-GGUF`, `bartowski/Llama-3.2-1B/3B-Instruct-GGUF`, `bartowski/microsoft_Phi-4-mini-instruct-GGUF`, `bartowski/Phi-3.5-mini-instruct-GGUF`, `unsloth/gemma-3n-E2B-it-GGUF`, `unsloth/Qwen3.5-0.8B-GGUF` (vlm), `unsloth/Qwen2.5-VL-7B-Instruct-GGUF` (vlm), `unsloth/gemma-4-E4B-it-GGUF`/`E2B` (vlm), `google/gemma-4-26B-A4B-it-qat-q4_0-gguf` (vlm), `unsloth/Qwen3.5-2B-GGUF`, `unsloth/Ministral-3-3B-Instruct-2512-GGUF`, `unsloth/gpt-oss-20b-GGUF:Q4_0` (hybrid only), `unsloth/granite-4.0-micro-GGUF`, `unsloth/Qwen3-VL-2B/4B-Instruct-GGUF` (vlm); qairt: `qualcomm/qwen3_4b`, `qualcomm/qwen3_4b_instruct_2507`, `qualcomm/qwen2_5_vl_7b_instruct` (w4a16).

## 8. Local server — full API (from `cli/server/docs/swagger.yaml`, `route.go`, handlers; v0.4.0)
Stack: Go + gin, `openai-go/v3` types, `sonic` JSON. Routes:
- `GET /` → 302 to `/docs/ui/` (Swagger UI); `GET /docs/swagger.yaml`; `GET /v1/` → text `GenieX-CLI is running` (health).
- `POST /v1/chat/completions`, `POST /v1/completions`, `POST /v1/logits`, `GET /v1/models`, `GET /v1/models/*model`.
- **Not present**: `/v1/embeddings` (issue #1149 open), `/v1/audio/*`, `/v1/images/*`, `/v1/responses`, tokenizer, model load/unload, pull endpoints.
- Middleware: `CORS` on all: `Access-Control-Allow-Origin: <--origins verbatim>` (single value; default `*`), `Allow-Methods: OPTIONS, GET, POST`, `Allow-Headers: Authorization, Content-Type, GenieX-KeepCache`, `Max-Age: 86400`, OPTIONS → 204. `auth.go` is empty → **no auth**; `api_key` any non-empty string (OpenAI SDK requires one; server ignores it). `GIL` middleware on `/v1/*`: a **global mutex serializes every request** ("Block rather than fail so briefly queued requests don't 429") — no concurrency, no batching.
- Keep-alive cache (`service/keepalive.go`): **exactly one model resident**; cache key = raw request `model` string + `ModelParam{NCtx, NGpuLayers, DeviceID, Spec{Type,DraftModel,NMax,NMin,PMin}}`. Any change of model/nctx/ngl/compute/spec_* → destroy current, load new. Idle sweep every 5 s; freed when idle > `--keepalive` s (idle measured from last request end; never freed mid-generation — fix #1322/#1324). No API to force unload/preload other than a warm-up request.
- **Warm-up request**: body with `messages: []` (or a single `system` message) loads the model (honouring `nctx/ngl/compute/spec_*`) and returns `200` with body `null`. `geniex run` uses this before its REPL.
- **Header `GenieX-KeepCache: true`**: the model is NOT `Reset()` before generation (default without header = reset conversation/KV state each request). `geniex run` sends this header on every turn while re-sending the full message history — i.e., use it for multi-turn prefix/KV reuse; omit it (or send a warm-up without it) to force a clean state.
- Error shapes: bind/validation → `400 {"error": "<msg>"}`; model missing → `404 {"error":"model not found"}`; unsupported param → `400 {"error":"a parameter in the request is not supported by the runtime","code":-100016}`; runtime failure → `500 {"error": "...", "code": <SDK int>}`; context overflow (blocking) → `400 {"error":{"message":"model context window exceeded; output truncated","type":"invalid_request_error","code":"context_length_exceeded"},"choices":[{"finish_reason":"length","message":{"role":"assistant","content":"<partial>"}}],"usage":{...}}`; in streaming, errors arrive as an SSE event `data:{"error":"...","code":N}` and the stream ends **without** `[DONE]`. `GET /v1/models/{m}` not found → `404` with body `null`.
- SDK error codes (`geniex.h`): `-100001` invalid input, `-100002` invalid device alias, `-100004` file not found, `-100005` network, `-100006` cancelled, `-100009` hub auth, `-100010` hub model not found, `-100011` rate limited, `-100013` not supported, `-100015` chipset unavailable, `-100016` param not supported by plugin, `-100201` model load failed, `-100203` invalid model, `-100301/302` plugin, `-200001` tokenization failed, `-200004` context length exceeded, `-200101` generation failed, `-200103` prompt too long, `-201001/1002` image load/format, `-201101/1102` audio load/format, `-201201` multimodal generation failed.

### 8.1 `POST /v1/chat/completions` request fields (bound onto `openai.ChatCompletionNewParams` + extras)
Standard used: `model` (required; `org/repo[:precision]`), `messages` (roles `system|user|assistant|tool`; content string or parts `text` | `image_url{url,detail}` | `input_audio{data}`), `max_completion_tokens` (default 2048; **the handler reads only `MaxCompletionTokens` — legacy `max_tokens` is parsed but ignored on chat completions in v0.4.0**, although docs examples use `max_tokens`), `temperature` (default 0.8 in swagger; sampler passes 0 if omitted), `top_p` (0.95), `presence_penalty`, `frequency_penalty`, `seed`, `stream`, `stream_options.include_usage`, `tools` (array; serialized to a JSON string and passed to the chat template).
GenieX extras: `enable_think` (bool, default true), `reasoning_format` (`none` default | `deepseek` | `deepseek-legacy` | `auto`), `top_k`, `min_p`, `repetition_penalty` (default 1.0), `grammar_path`, `grammar_string`, `nctx` (llama_cpp; default server `--nctx`; auto-raised to `max_completion_tokens` if smaller), `ngl`, `compute` (`cpu|gpu|npu|hybrid`), `spec_type` (`draft-mtp|draft-eagle3|draft-simple|ngram-simple|ngram-map-k|ngram-map-k4v|ngram-mod|ngram-cache`), `spec_draft_model` (must be pulled beforehand or absolute GGUF path — server never auto-downloads), `spec_n_max` (3), `spec_n_min`, `spec_p_min`.
**Ignored/unsupported on chat completions (verified in `chat.go` at tag v0.4.0)**: `stop` (not forwarded to GenerationConfig!), `grammar_path`/`grammar_string` (bound but NOT copied into `SamplerConfig` → server-side grammar is a no-op in v0.4.0; CLI/Python grammar works), `max_tokens`, `n`, `logprobs`/`top_logprobs`, `logit_bias`, `response_format`/JSON mode, `tool_choice` (schema lists it; unused), `parallel_tool_calls`, `image_url.detail`.
Message handling: LLM (text-only) models accept only string or `text` parts — an `image_url`/`input_audio` part → `400 {"error":"not support content part type"}`. VLM: `image_url.url` and `input_audio.data` accept local path (Windows drive letters handled; `file://` optional), `http(s)://` (server fetches), `data:<mime>;base64,...` (or percent-encoded); bytes are sniffed, **WebP converted to PNG**, written to a temp file `uri-*<ext>` and deleted after generation. **Only media parts of the LAST message are passed to the model** (`prepareVLM` reads `messages[len-1].Contents`); earlier images stay as template placeholders — keep images only in the final user turn (docs' tool-call note also says drop images on follow-up turns). Assistant `tool_calls` history is re-serialized as text `<tool_call>{"name":"%s","arguments":"%s"}</tool_call>`; `tool` role messages must have **string** content (`tool_call_id` required to be recognised).
Model routing: `ModelGetType(name)`; if `spec_type` set on a VLM-classified model → LLM path, media dropped with a warning.
### 8.2 Responses
- Non-streaming (plain): serialized `openai.ChatCompletion{Choices, Usage}` → JSON has `choices[0].message.{role,content}`, `finish_reason` (`stop|length|tool_calls`), `usage.{prompt_tokens,completion_tokens,total_tokens}`; `id`/`created`/`model` are empty/zero (older captures show `"id":""`, extra empty fields like `refusal`, `audio`, `logprobs:{content:null,refusal:null}`). With `reasoning_format` separating: custom body `{"object":"chat.completion","choices":[{"index":0,"message":{"role":"assistant","content":"...","reasoning_content":"..."},"finish_reason":"stop"}],"usage":{...}}` (no id/created/model). Tool call: `message.tool_calls=[{"id":"call_<rand uint32>","type":"function","function":{"name","arguments"}}]`, `finish_reason:"tool_calls"`, `content` empty.
- Streaming (`stream:true`): SSE (`Content-Type: text/event-stream`), gin-encoded lines `data:{json}\n\n`, terminal `data:[DONE]\n\n`. Chunk shape: `{"object":"chat.completion.chunk","choices":[{"index":0,"delta":{"role":"assistant","content":"tok"} or {"reasoning_content":"tok"} or {"tool_calls":[...]}, "finish_reason":null}]}`; final `{"object":"chat.completion.chunk","choices":[{"index":0,"delta":{},"finish_reason":"stop|length|tool_calls"}]}`; if `stream_options.include_usage` → extra `{"object":"chat.completion.chunk","choices":[],"usage":{...}}` before `[DONE]`. **No `id`, `created`, `model` on chunks.** With `tools`, the whole generation is buffered and emitted as ONE `tool_calls` chunk at the end (no incremental streaming); on parse failure falls back to a single content chunk with normal finish_reason.
- Usage: `completion_tokens_details.accepted_prediction_tokens/rejected_prediction_tokens` (MTP stats) added on `main` after v0.4.0 (PR #1336) — not in v0.4.0.
- finish_reason mapping from SDK stop_reason: `length`→`length`; `user`/`eos`/`stop_sequence`/other→`stop`.
### 8.3 Thinking / reasoning
`enable_think=false` → model doesn't think (chat-template flag; forced true with warning on non-thinking models in Python). `reasoning_format=deepseek|deepseek-legacy|auto` → server splits via `cli/internal/thinkfsm` (token-level FSM handling `<think>…</think>`, gpt-oss `<|channel|>analysis<|message|>…<|end|>…<|start|>assistant`, Gemma 4 `<|channel>thought\n…<channel|>`); marker tokens are consumed; reasoning goes to `message.reasoning_content` / `delta.reasoning_content`. Ignored when `tools` present ("tool parsing needs the raw tagged text"). Default (`none`) keeps `<think>` inline in `content` — a UI must parse it itself in that mode.
### 8.4 Tool calling
`tools` array (OpenAI schema `{"type":"function","function":{name,description,parameters}}`) → JSON string → chat template `tools`. Response text is scanned for the **first balanced `{...}` object** with string `name` and object/string `arguments` (`utils/toolcall.go`, "match tool-call JSON by braces instead of tags", v0.4.0) — works for `<tool_call>{...}</tool_call>` and fenced ```json blocks. **Only one tool call per turn**; parallel tool calls unsupported. Gemma 4's `<|tool_call>call:NAME{key:<|"|>str<|"|>,...}<tool_call|>` syntax parser landed on `main` after v0.4.0 (PR #1345) — not in the installed release (Gemma 4 GGUF tool calls fall back to plain text). Works with VLMs. Docs Qwen3-VL tips: (1) system prompt spelling out `<tool_call>{"name": "...", "arguments": {...}}</tool_call>`; (2) on the follow-up turn drop `tools=` and drop the image content. Docs full example (Python, `qualcomm/Qwen3-VL-4B-Instruct`, `web_search` via `ddgs`) copied in §12.
### 8.5 `POST /v1/completions` (raw, no chat template; FIM)
Fields: `model` (LLM only; VLM → 400 "completions is only supported for LLM models"), `prompt` (string, or single-element string array; token arrays → 400), `max_tokens` (default 16), `echo`, `stop` (string|array; forwarded — **QAIRT rejects stop → 200 with empty text, `-100016` in log**, issue #1341), `temperature`, `top_p`, `top_k`, `min_p`, `repetition_penalty`, `presence_penalty`, `frequency_penalty`, `seed`, `stream`, `stream_options.include_usage`, `nctx`, `ngl`, `compute`. Rejected 400: `suffix` ("include the model's FIM tokens in prompt"), `n>1`, `best_of>1`, `logprobs`, `logit_bias`. Response `{"object":"text_completion","choices":[{"index":0,"text":"...","finish_reason":"stop|length"}],"usage":{...}}`; stream chunks `{"object":"text_completion","choices":[{"index":0,"text":"tok","finish_reason":null}]}` then finish chunk, optional usage chunk, `[DONE]`; echo emitted as first chunk. Context overflow → 400 body with `choices[0].text` partial. Docs example: `{"model":"unsloth/Qwen2.5-Coder-3B-GGUF:Q4_0","prompt":"<|fim_prefix|>def fibonacci(n):\n    <|fim_suffix|>\n    return a<|fim_middle|>","max_tokens":64,"temperature":0.2,"stop":["<|endoftext|>"],"stream":false}`.
### 8.6 `POST /v1/logits` (prefill-only raw logits; not OpenAI logprobs)
Request `{"model","input_ids":[int...] (required, pre-tokenized — server has no tokenizer endpoint),"last_only":false,"top_n":20 (0=full vocab),"nctx","ngl","compute"}`; LLM only. Response `{"model","n_rows","vocab_size","top_n","rows":[{"token_ids":[...],"logits":[...]}]}` (`token_ids` omitted when top_n=0). Intended for perplexity/MMLU.
### 8.7 Models endpoints
`GET /v1/models` → `{"object":"list","data":[{"id":"<name>[:<precision>]","owned_by":"<org>"}]}` — one entry per cached precision; precision suffix omitted for QAIRT (`N/A`). `GET /v1/models/{name}[:{precision}]` → `{"id","owned_by"}`; no precision → lexicographically-first cached precision. Runtime/type are NOT exposed here (use `geniex list --format json`).

## 9. Speculative decoding (tutorial + source)
`llama_cpp`-only, text-only (on `qairt` ignored with warning; VLM → LLM path, media dropped). `draft-*` types need `--draft-model`/`spec_draft_model` trained against the exact target ("mismatched pair fails at load time"); `ngram-*` are self-speculative. Docs pair: target `google/gemma-4-26B-A4B-it-qat-q4_0-gguf:Q4_0` + draft `RachidAR/gemma-4-26B-A4B-it-qat-assistant-q4_0-gguf:Q4_0` (~20 GB disk, both resident). Server example body: `{"model":"google/gemma-4-26B-A4B-it-qat-q4_0-gguf:Q4_0","messages":[{"role":"user","content":"Hello! Briefly introduce yourself."}],"spec_type":"draft-mtp","spec_draft_model":"RachidAR/gemma-4-26B-A4B-it-qat-assistant-q4_0-gguf:Q4_0","spec_n_max":3,"nctx":8192,"max_completion_tokens":2048,"temperature":0.8,"top_p":0.95,"stream":false}`. `spec_*` are part of the cache key ("changing any of them rebuilds the model"). Setup failure is non-fatal (`speculative decoding setup failed; falling back to plain decoding`). Profiling `draft accept: a/b`.

## 10. Context, keepalive, concurrency, performance tips (consolidated)
- `--nctx` default 4096 (llama_cpp; up to model max; more KV memory); server auto-raises to `max_completion_tokens`. QAIRT fixed. "Context length exceeded" → CLI: raise `--nctx` (llama_cpp) or `--sliding-window` (qairt) or longer-context bundle; server: 400 `context_length_exceeded` (partial output) / SSE error `-200004`.
- KV cache save/load exists in the C API/Python (`save_kv_cache(path)`/`load_kv_cache(path)`, `geniex_llm_save_kv_cache`) but is NOT exposed on the HTTP server.
- Concurrency: one model, one request at a time (GIL); model switch = full unload/reload; keepalive 300 s default.
- QAIRT perf (issue #1266, X Elite, `ai-hub-models/Qwen3-4B-Instruct-2507`): healthy 17–19 tok/s decode, ~1,230–1,340 tok/s prefill (prefill in 128-token chunks); an intermittent degraded state (~1.5 s fixed latency per graphExecute → 0.64 tok/s) is an open bug. QAIRT spins a "clock-keeper" CPU thread by default (`GENIEX_CLOCK_KEEPER_THREADS=0` disables; +2.9 W system power for no gain on X2 Plus, issue #1330).
- llama.cpp on Adreno: k-quants ~25% slower than legacy quants (issue #1225). IQ-9075 examples: gemma-4-E4B Q4_0 npu 9.5 tok/s vs cpu 13 tok/s for the 26B.
- Both runtimes: default `npu`; docs recommend `hybrid` explicitly for llama.cpp's faster HTP+CPU scheduling.

## 17. Discrepancies / gotchas to remember
1. Docs CLI reference lists `--enable-json`; not in v0.4.0 binary. 2. Docs say `--compute cpu` on AI Hub model "returns an error"; SDK/serve coerce with a warning. 3. Docs server examples use `max_tokens`; handler honours only `max_completion_tokens` (default 2048). 4. `grammar_path`/`grammar_string` and `stop` on `/v1/chat/completions` are not applied in v0.4.0. 5. `notes/run.md` describes `--device` and hybrid-as-default (outdated). 6. `README` Android version 0.3.1 vs AAR v0.4.0. 7. Streaming chunks lack `id/created/model`; blocking JSON has empty `id`. 8. Only last-message media used; images to LLM → 400. 9. One tool call per turn; Gemma-4 tool syntax not parsed in v0.4.0. 10. `GenieX-KeepCache` header is undocumented (source only). 11. Warm-up (`messages: []`) is undocumented but used by `geniex run`. 12. `/v1/models` gives no runtime/type/size — use `geniex list --format json`. 13. `geniex pull` is interactive without `:precision`; drive it with explicit precision + `--model-type` and `--skip-update`. 14. `--origins` is a single literal value, not a list. 15. HTTP server keeps only one model resident; switching models or nctx/compute reloads (seconds). 16. Server-side audio needs no SoX (only CLI `/mic`).
