# Research: shipping a desktop-quality GenieX UI on Windows 11 ARM64 (Node/React) — Aug 2026

## 0. Local facts that shape the choice (verified on this machine)
- No Rust, no VS Build Tools → anything needing node-gyp or cargo costs a multi-GB toolchain install. Node 24 arm64 + WebView2 (native ARM64) are present.
- `geniex.exe` is NOT a single-file binary: `C:\Users\stama\AppData\Local\GenieX CLI\` = `geniex.exe` (34 MB) + `geniex.dll` + `llama_cpp\` (ggml.dll, ggml-hexagon.dll, ggml-opencl.dll, llama.dll, mtmd.dll, libomp140.aarch64.dll, libggml-htp-v73/v75/v79/v81.so, geniex_plugin.dll) + `qairt\` (geniex_core.dll, geniex_vlm.dll, geniex-proc*.dll, htp-files\). Installed by Inno Setup (`unins000.exe`). Consequence: a Tauri "sidecar" of the bare exe will not run; either bundle the whole folder as resources or (recommended) spawn the user's installed CLI at `%LOCALAPPDATA%\GenieX CLI\geniex.exe` and delegate updates to `geniex update`.
- `geniex serve --help`: `--host 127.0.0.1:18181`, `--origins` default `*` (CORS already open, so any WebView/browser origin can call it directly), `--keepalive 300`, `--nctx 4096`, `--ngl -1`, `--compute cpu|gpu|npu|hybrid`, `--https/--certfile/--keyfile`, global `--data-dir`, `--log`, `--skip-update` (always pass when spawning to avoid update-check latency).

## 1. Tauri v2 on Windows ARM64
- Versions: `@tauri-apps/cli` 2.11.4 with `@tauri-apps/cli-win32-arm64-msvc` (native CLI binary exists). https://registry.npmjs.org/@tauri-apps/cli/latest
- Rust: `aarch64-pc-windows-msvc` is Tier 1 WITH host tools → rustc/cargo run natively; `winget install Rustlang.Rustup`, `rustup default stable-msvc`. https://doc.rust-lang.org/nightly/rustc/platform-support.html , https://v2.tauri.app/start/prerequisites/
- VS Build Tools 2022 (17.4+ has a native ARM64 installer): need "Desktop development with C++" + individual component "MSVC v143 - VS 2022 C++ ARM64 build tools (Latest)" + Windows 11 SDK. This is the biggest cost (several GB, not installed today). https://v2.tauri.app/distribute/windows-installer/ , https://learn.microsoft.com/en-us/visualstudio/install/visual-studio-on-arm-devices?view=vs-2022
- Build: on an ARM64 host `tauri build` targets host by default; explicit: `rustup target add aarch64-pc-windows-msvc && npm run tauri build -- --target aarch64-pc-windows-msvc`.
- Installers: NSIS only for arm64 (WiX v3 MSI does not support arm64). NSIS installer runs x86-emulated, app is native arm64. Set `bundle.targets: ["nsis"]` to avoid the MSI path (which on ARM hosts hit "no TLS backend" downloading WiX, tauri#11294, and MSI+externalBin failures tauri#14681; MSI also needs the VBSCRIPT optional feature tauri#13752). https://github.com/tauri-apps/tauri/issues/11294 , https://github.com/tauri-apps/tauri/issues/14681
- WebView2: bundled Evergreen bootstrapper modes (downloadBootstrapper default, embedBootstrapper ~1.8 MB, offlineInstaller ~127 MB, fixedVersion ~180 MB); Win11 ships native ARM64 WebView2 already. Chromium-based → fetch/ReadableStream/SSE streaming fine. CSP must allow `connect-src http://127.0.0.1:18181`; WebView origin is `http://tauri.localhost` (fine with geniex `--origins *`).
- Sidecar: `bundle.externalBin: ["binaries/geniex"]` with file `geniex-aarch64-pc-windows-msvc.exe`; capability `shell:allow-execute`/`shell:allow-spawn` with `{ name, sidecar: true, args: [...] }`; JS `Command.sidecar('binaries/geniex')` from `@tauri-apps/plugin-shell`. Gotcha above: needs the DLL folders too (`bundle.resources`) — or just spawn the installed CLI via `Command.create` with an allow-listed absolute path. https://v2.tauri.app/develop/sidecar/
- Tray: `tauri = { features = ["tray-icon"] }`, JS `TrayIcon.new()`/Rust `TrayIconBuilder`, menus + click events; works on Windows. https://v2.tauri.app/learn/system-tray/
- Updater: `tauri-plugin-updater`, mandatory minisign keys (`tauri signer generate`), static JSON with `windows-aarch64` key, NSIS supported, `installMode` passive/basicUi/quiet, app exits during install (`on_before_exit` hook). https://v2.tauri.app/plugin/updater/
- Big gotcha for a Node team: no Node runtime in production. Backend = Rust commands (rusqlite bundled, portable-pty, tokio::process all compile on aarch64-msvc), or ship Node as a sidecar (Node 24 SEA via postject / Node ≥25.5 `--build-sea`; or Bun ≥1.3.10 `bun build --compile --target=bun-windows-arm64`) — native .node addons then have to be shipped and located manually. https://nodejs.org/api/single-executable-applications.html , https://bun.com/blog/bun-v1.3.10
- Net: ~10 MB installer, lowest RAM, first-class tray/updater/sidecar; requires installing Rust + VS ARM64 build tools and writing (some) Rust.

## 2. Electron on Windows ARM64
- Versions: electron 43.4.0 stable (Chromium 150, Node 24.17, V8 15.0; series supported to Jan 2027), 44.0.0-beta.3; engines Node ≥22.12. Prebuilt `win32-arm64` zips have existed since 5.0.8; on a native arm64 host `npm i electron` downloads arm64 automatically (else `npm_config_arch=arm64`). https://www.electronjs.org/blog/electron-43-0 , https://www.electronjs.org/docs/latest/tutorial/windows-arm , https://registry.npmjs.org/electron
- No compile toolchain needed IF every native module is N-API with win32-arm64 prebuilds — true for the set you need (see §5). Set electron-builder `npmRebuild: false` (default true would invoke node-gyp/@electron/rebuild, which fails without VS Build Tools) and `asarUnpack: ["**/*.node", "node_modules/@img/**", "node_modules/sharp/**"]`.
- electron-builder 26.15.3: `electron-builder --win nsis --arm64` (or `--x64 --arm64` → single unified NSIS installer that picks the arch at install time). Its `app-builder-bin` 4.2.0 ships `win/arm64/app-builder.exe`, so packaging runs natively on the Snapdragon box; NSIS makensis is x86 under emulation (fine). Squirrel.Windows arm64: historically unsupported (electron-builder#7492 closed not-planned) → use NSIS. https://www.electron.build/docs/architecture/ , https://www.electron.build/docs/nsis/ , https://registry.npmjs.org/electron-builder/latest , https://github.com/electron-userland/electron-builder/issues/7492
- Auto-update: `electron-updater` NsisUpdater; unified multi-arch installer → one `latest.yml`. https://www.electron.build/auto-update
- Tray: built-in `Tray`; child_process/utilityProcess for `geniex serve`; full Node in main (fs, better-sqlite3, node:sqlite via Node 24.17, node-pty).
- Tooling: electron-vite 5.0.0 (peer Vite ^5|^6|^7; 6.0.0-beta.1 for Vite 8). https://registry.npmjs.org/electron-vite
- Cost: ~120–170 MB install, higher idle RAM; but the LLM runtime dominates anyway.

## 3. Local Node server + browser / PWA
- Zero toolchain: Node 24 arm64 + Vite 8.2.1 (engines ^20.19||>=22.12) + Hono (`@hono/node-server`, `streamSSE`) or Fastify; child_process spawn of the installed geniex; fs; SQLite via better-sqlite3 prebuilt or built-in `node:sqlite`.
- Installable PWA: Chrome/Edge desktop now require only a manifest (name/icons/start_url/display) served over HTTPS OR localhost/127.0.0.1 (any port); service worker no longer required. Edge on Win11 ARM64 is native. Use `display: "window-controls-overlay"` for a desktop feel. https://developer.chrome.com/blog/update-install-criteria , https://web.dev/articles/install-criteria
- Missing: system tray, single-instance/lifecycle control, auto-updater, close-to-tray. Node tray packages: `tray-icon-node` 0.1.2 has no win32-arm64 target; `windows-trayicon`/`ctray` need node-gyp; `node-systray-v2` ships foreign binaries (arm64-win unverified) → practical hack is a PowerShell `System.Windows.Forms.NotifyIcon` helper spawned by Node, or accept no tray. https://registry.npmjs.org/tray-icon-node/latest
- Best as a fast prototype / fallback mode; the same Vite+React+Node code can later be wrapped by Electron.

## 4. Other Node-ish shells (all ruled out for native ARM64 Windows)
- Neutralinojs: official binaries x64 only on Windows (runs emulated); native arm64 requires building from source with a C++ toolchain. https://neutralino.js.org/docs/distribution/overview/
- Electrobun: Windows x64 only in 2026 releases (Bun itself got Windows arm64 in v1.3.10, but Electrobun hasn't). https://github.com/blackboardsh/electrobun/releases , https://github.com/oven-sh/bun/issues/9824
- NW.js: no win-arm64 builds. Gluon/Socket: stale. Wails (Go; WebView2) does support windows/arm64 but is Go, not Node — only if you accept a Go backend.

## 5. Native module ARM64 prebuild status (Node 24 arm64 host)
- better-sqlite3 13.0.3: N-API (node-addon-api 8), Node ≥22, prebuilt `win32-arm64` shipped inside the package (no prebuild-install download, works in Electron 43 without rebuild). https://registry.npmjs.org/better-sqlite3/latest , https://github.com/WiseLibs/better-sqlite3/releases
- node-pty 1.1.0 (latest): tarball has `prebuilds/win32-arm64` (+ win32-x64, darwin-*), N-API; ConPTY needs Win10 1809+; Spectre libs only if building from source. `@lydell/node-pty` 1.2.0-beta.15 offers `@lydell/node-pty-win32-arm64` as optional dep (smaller). https://cdn.jsdelivr.net/npm/node-pty@1.1.0/prebuilds/ , https://registry.npmjs.org/@lydell/node-pty/latest , https://github.com/microsoft/node-pty
- sharp 0.35.3: prebuilt Windows ARM64 (`@img/sharp-win32-arm64`), Node ≥20.9. https://sharp.pixelplumbing.com/install/
- libsql 0.5.29: NO `@libsql/win32-arm64-msvc` → avoid. https://registry.npmjs.org/libsql/latest
- node:sqlite: built into Node 24 (unflagged since 22.13/23.4; RC status from 25.7; stable in 26) — zero deps, DatabaseSync API, extensions supported; mark `external: ['node:sqlite']` in Vite/electron-vite (vite discussion #19278). https://nodejs.org/api/sqlite.html
- sql.js / @sqlite.org/sqlite-wasm: portable fallback, no native deps.

## 6. Next.js 16 vs Vite + React for this app
- Next.js 16.3.1 (Node ≥20.9, React 18.2/19). Route handlers/SSE require a running Next server: in Electron you must run `next start`/custom server inside main (startup latency, port juggling; standalone-output + custom-server static/route pitfalls, vercel/next.js#75283); in Tauri there is no Node, so only `output: 'export'` (no route handlers). RSC/SSR buys nothing for a local-first UI. https://github.com/vercel/next.js/discussions/75283
- Vite 8.2.1 + React 19 SPA (React Router 7 or TanStack Router) + Hono/Fastify backend: trivial SSE proxy (`streamSSE`), `child_process` supervisor for `geniex serve`, fs, SQLite; the same bundle serves Electron renderer, Tauri WebView, and PWA. Recommended.

## 7. Recommendation matrix
| Shell | Toolchain to install now | Native arm64 status | Tray | Auto-update | Bundle geniex | Backend | Verdict |
|---|---|---|---|---|---|---|---|
| Electron 43.4 + electron-vite 5 + electron-builder 26.15 (NSIS --arm64) | none (Node 24 present) | full (prebuilt win32-arm64; app-builder-bin win/arm64) | built-in | electron-updater | spawn installed CLI (or bundle folder as extraResources) | Node in main/utilityProcess | Primary recommendation: fastest to desktop-quality with zero compile deps |
| Tauri 2.x (CLI 2.11.4) + WebView2 | rustup (aarch64 host) + VS Build Tools 2022 w/ MSVC v143 ARM64 + Win11 SDK | full; NSIS only (no MSI) | tray-icon feature | tauri-plugin-updater (windows-aarch64) | sidecar naming `-aarch64-pc-windows-msvc.exe` + resources | Rust commands, or Node/Bun SEA sidecar | Best size/RAM/native feel; adopt later if you accept Rust |
| Vite + Hono + Edge/Chrome PWA | none | n/a (browser native) | none (PS hack) | none | spawn installed CLI | Node | Prototype / fallback mode; share code with Electron |
| Neutralino / Electrobun / NW.js | C++ toolchain / n.a. | no native win-arm64 | — | — | — | — | Reject |

Suggested architecture: framework-agnostic `core` Node package (geniex process supervisor, SSE proxy, SQLite via better-sqlite3 or node:sqlite, file ops, node-pty terminal) + Vite/React 19 UI + thin Electron main (tray, updater, single-instance) with the same server runnable headless for PWA mode; keep a Tauri wrapper as an optional later target (Rust re-implementation of `core` or SEA sidecar).

## Key gotchas checklist
1. Spawn `%LOCALAPPDATA%\GenieX CLI\geniex.exe serve --skip-update [--compute npu --nctx ...]`; don't try to ship the bare exe as a sidecar (DLL/.so plugin folders required).
2. electron-builder: `npmRebuild: false`, NSIS target, `asarUnpack` for `.node` + sharp/@img; avoid Squirrel/MSI on arm64.
3. Tauri: NSIS only; install "MSVC v143 ARM64 build tools"; CSP connect-src for 127.0.0.1:18181; no Node at runtime.
4. Avoid libsql on ARM64 Windows; prefer better-sqlite3 13 or node:sqlite.
5. Vite/electron-vite: externalize `node:sqlite`, `better-sqlite3`, `node-pty`, `sharp` from the main bundle.
6. Unsigned NSIS installers trip SmartScreen; plan code signing (Azure Trusted Signing) if distributing.
7. Electron 44 drops ia32 only; arm64 unaffected. Vite 8 needs electron-vite 6 beta (or stay on Vite 7 with electron-vite 5).
